# 后台管理接口约定（v1）

后台网页与接口都内置在 pestai-server 中，不单独部署：

- 网页：`/admin/`（静态文件 `server/src/main/resources/static/admin/`，Vue 3 + Element Plus + ECharts，库文件放在 `static/admin/vendor/`，不依赖外网 CDN）
- 接口：`/admin/api/**`（不在 `/pestai/v1/` 前缀下，不使用 App 的 JWT）
- 访问：公网直接访问 `http://公网IP/admin/`（Nginx 已把 `/` 全部转发到后端）

响应格式与 App 接口相同：`{"code":0,"message":"ok","data":...}`，JSON 字段下划线命名，时间格式 `yyyy-MM-dd HH:mm:ss`。

## 一、登录与安全

| 项 | 约定 |
|---|---|
| 会话 | 登录成功后服务器建立 HttpSession，Cookie 为 HttpOnly、SameSite=Strict；30 分钟无操作过期 |
| CSRF | 登录 / `auth/me` 返回 `csrf_token`；除 GET 外的所有请求必须带请求头 `X-CSRF-Token`，不符返回 40301 |
| 未登录 | 40101「请先登录」，网页跳到登录页 |
| 初始密码未修改 | 除 `auth/me`、`auth/password`、`auth/logout` 外返回 40302「请先修改初始密码」 |
| 登录锁定 | 同一账号或同一 IP 连续输错 5 次锁定 15 分钟，期间返回 42901「登录失败次数过多，请 N 分钟后再试」 |
| 初始管理员 | 后端启动时若没有管理员，创建 `admin`，密码取环境变量 `PESTAI_ADMIN_INITIAL_PASSWORD`（部署脚本首次安装时随机生成并在部署结果中显示）；未设置时随机生成并在启动日志中打印一次；`must_change_password = true` |
| 修改密钥 | 修改或恢复「密钥类」配置必须同时提交 `admin_password`（当前管理员密码），错误返回 40001「管理员密码不正确」 |
| 操作日志 | 所有写操作（含登录成功 / 失败、退出）写入 t_admin_log：管理员、动作、对象、摘要、IP、时间；摘要中不得出现密钥明文与用户密码 |

错误码：沿用 App 的 ErrorCode（40001 参数错误、40101 未登录、40301 无权限、42901 太频繁、50001 服务器错误），新增 40302。

### 1.1 auth

| 方法 | 路径 | 请求 | 返回 data |
|---|---|---|---|
| POST | admin/api/auth/login | `{username, password}` | `{username, must_change_password, csrf_token}` |
| POST | admin/api/auth/logout | — | null |
| GET | admin/api/auth/me | — | `{username, must_change_password, csrf_token}`；未登录 40101 |
| POST | admin/api/auth/password | `{old_password, new_password}`（新密码 ≥ 10 位，同时含字母和数字，不能与旧密码相同） | null（成功后 must_change_password = false） |

## 二、数据统计

| 方法 | 路径 | 返回 data |
|---|---|---|
| GET | admin/api/stats/overview | `{users:{total, today_new, active_7d, disabled}, recognitions:{total, today, success_rate_7d}, ai:{questions_total, questions_today, image_question_ratio_7d}, sms:{today, last_7d}}`（比率为 0–1 小数） |
| GET | admin/api/stats/trend?days=7\|30 | `{dates:["2026-10-01",...], new_users:[..], active_users:[..], recognitions:[..], recognition_success:[..], ai_questions:[..], sms_sent:[..]}`（各数组与 dates 等长，按天，含今天） |
| GET | admin/api/stats/distribution | `{modes:[{name,value}], top_results:[{name,value}]（识别成功的 top_name 前 10）, identities:[{name,value}], crops:[{name,value}]（用户作物前 10）}` |

「活跃」= 当天有登录、识别或 AI 提问之一。

## 三、用户管理

用户状态 `status`：`NORMAL`（t_user.status = 0）/ `DISABLED`（= 1）。注销账号沿用 App 的注销逻辑（删除该用户全部数据），注销后不再出现在列表中。

| 方法 | 路径 | 请求 | 返回 data |
|---|---|---|---|
| GET | admin/api/users?keyword=&status=&page=1&size=20 | keyword 匹配手机号或昵称 | PageVO：`{list:[UserRow], total, has_more}` |
| GET | admin/api/users/{id} | — | UserDetail |
| GET | admin/api/users/{id}/recognitions?page=&size= | — | PageVO：`{list:[{id, mode, status, top_name, confidence, severity, image_url, created_at, deleted}], ...}`（含用户已删除的记录，`deleted` 为 true） |
| GET | admin/api/users/{id}/sessions?page=&size= | — | PageVO：`{list:[{session_id, title, message_count, updated_at}], ...}` |
| GET | admin/api/sessions/{id}/messages | — | `[{role, content, image_urls, reasoning_content, created_at}]` |
| POST | admin/api/users/{id}/disable | `{reason}`（可空） | null（同时强制下线） |
| POST | admin/api/users/{id}/enable | — | null |
| POST | admin/api/users/{id}/logout | — | null（token_version + 1，所有设备需重新登录） |
| PUT | admin/api/users/{id}/profile | `{nickname, identity, crops, clear_avatar}`（identity 为三种身份之一或 null；crops 逗号分隔） | UserDetail |
| POST | admin/api/users/{id}/reset-password | — | `{temp_password}`（12 位随机，含字母和数字；同时强制下线；只返回这一次） |
| DELETE | admin/api/recognitions/{id} | — | null（彻底删除记录与照片文件） |
| DELETE | admin/api/sessions/{id} | — | null（删除会话、消息与聊天图片） |
| POST | admin/api/users/{id}/deactivate | `{confirm_phone}`（必须等于该用户完整手机号） | null（注销并删除全部数据，不发短信） |

UserRow：`{id, phone, nickname, avatar_url, identity, crops, status, created_at, last_login_at, recognition_count, ai_question_count}`（后台显示完整手机号）。

UserDetail：UserRow 全部字段 + `{region, recovery_code_generated, sms_verified_at, session_count}`。

## 四、系统配置（API Key 与模型）

配置项（key 与 `.env` / 环境变量同名）：

| 分组 group | key | 说明 | 密钥类 |
|---|---|---|---|
| vision（通义千问识图） | DASHSCOPE_API_KEY | DashScope API Key（识图与语音识别共用） | 是 |
| vision | VISION_MODEL | 识图模型名，默认 qwen3.8-max | 否 |
| chat（DeepSeek 问答） | DEEPSEEK_API_KEY | DeepSeek API Key | 是 |
| chat | CHAT_MODEL | 问答模型名，默认 deepseek-flash | 否 |
| asr（语音识别） | ASR_MODEL | 语音识别模型名，默认 qwen3-asr-flash | 否 |
| sms（阿里云短信） | ALIYUN_SMS_ACCESS_KEY_ID | AccessKey ID | 是 |
| sms | ALIYUN_SMS_ACCESS_KEY_SECRET | AccessKey Secret | 是 |
| sms | ALIYUN_SMS_SIGN_NAME | 短信签名 | 否 |
| sms | ALIYUN_SMS_TEMPLATE_CODE / _RESET / _REBIND / _CHANGE_PHONE / _VERIFY | 各场景模板编号 | 否 |

生效顺序：后台设置的值（t_system_config，密钥类 AES-GCM 加密保存）> 环境变量 / `.env` > 默认值。修改后立即生效，不用重启。

| 方法 | 路径 | 请求 | 返回 data |
|---|---|---|---|
| GET | admin/api/config | — | `[{key, label, group, secret, value, source, updated_at, updated_by}]`；密钥类 `value` 为掩码（前 3 位 + `****` + 后 4 位，未配置为空串），非密钥类为明文；`source` 为 `ADMIN` / `ENV` / `DEFAULT` / `NONE` |
| PUT | admin/api/config/{key} | `{value, admin_password}`（密钥类必须带 admin_password；value 去掉首尾空白，不能为空） | 更新后的该项 |
| DELETE | admin/api/config/{key} | `{admin_password}`（密钥类必须带） | 恢复后的该项（改回使用 `.env` / 默认值） |
| POST | admin/api/config/test/{group} | sms 时 `{phone}`（发送一条测试验证码） | `{ok, message, latency_ms}`；vision / chat / asr 用当前配置发一次最小请求 |

## 五、操作日志

| 方法 | 路径 | 返回 data |
|---|---|---|
| GET | admin/api/logs?action=&page=1&size=20 | PageVO：`{list:[{id, admin, action, target, detail, ip, created_at}], ...}`，按时间倒序 |

action 取值：`LOGIN`、`LOGIN_FAILED`、`LOGOUT`、`CHANGE_PASSWORD`、`USER_DISABLE`、`USER_ENABLE`、`USER_LOGOUT`、`USER_PROFILE`、`USER_RESET_PASSWORD`、`USER_DEACTIVATE`、`RECOGNITION_DELETE`、`SESSION_DELETE`、`CONFIG_UPDATE`、`CONFIG_RESET`、`CONFIG_TEST`。

## 六、App 语音识别接口（供 App 语音输入使用）

| 方法 | 路径 | 请求 | 返回 data |
|---|---|---|---|
| POST | pestai/v1/ai/asr | multipart 字段 `audio`：WAV（PCM 16 位、16kHz、单声道），时长 ≤ 60 秒、≤ 2MB；需要登录 | `{text}` |

- 后端用 DashScope 的语音识别模型（ASR_MODEL，默认 qwen3-asr-flash）识别，使用 DASHSCOPE_API_KEY。
- 没识别出文字：40001「没有听清，请再说一遍」；超过频率（每人每分钟 20 次）：42901；识别服务不可用：50201「语音识别暂不可用，请稍后再试」。
- 音频只用于本次识别，不保存。

## 七、后台网页

静态文件在 `server/src/main/resources/static/admin/`，无构建步骤：`index.html` + `css/admin.css` + `js/`（`util.js` 工具、`api.js` 接口封装、`router.js` hash 路由、`components.js` 公共组件、`pages/*.js` 各页面、`app.js` 入口）。库文件放在 `static/admin/vendor/`（Vue 3.5.42、Element Plus 2.14.5、icons-vue 2.3.2、ECharts 5.6.0，见 vendor/README.md），不使用 WebJars（Maven Central 上 Element Plus 的 WebJar 最新只有 2.1.10）也不使用公网 CDN。

| 路由 | 页面 |
|---|---|
| `#/login` | 登录（42901 锁定提示） |
| `#/password-required` | 强制修改初始密码 |
| `#/dashboard` | 数据统计 |
| `#/users`、`#/users/{id}` | 用户列表、用户详情（停用 / 启用、强制下线、编辑资料、重置密码、注销、识别记录、AI 对话） |
| `#/config` | 系统配置（密钥类修改 / 恢复需管理员密码；测试连接） |
| `#/logs` | 操作日志 |

对后端的要求：

- `/admin`、`/admin/` 转发到 `/admin/index.html`；网页与 `/admin/vendor/**` 静态文件不需要登录。
- `auth/login` 不校验 CSRF（登录前还没有令牌）；其他非 GET 请求带 `X-CSRF-Token`。网页收到 40301 时会重新取一次 `auth/me` 再重试一次。
- 网页在浏览器里编译 Vue 模板：如果设置 Content-Security-Policy，`script-src` 需要 `'unsafe-eval'`，`img-src` 需要包含识别照片 / 聊天图片 / 头像所在的地址。
- 修改网页后把 `index.html` 里 `?v=` 的数字加一，避免浏览器使用旧缓存。

网页对第八节「模型自动备用」的显示（旧版后端缺少这些字段时按 0 / 不显示处理）：

- 系统配置：「语音识别」与「阿里云短信」之间的「自动备用」卡片；AI_FALLBACK_ENABLED 显示为开关，确认后 `PUT config/AI_FALLBACK_ENABLED {value:"true"|"false"}`，两个备用模型用修改弹窗。
  「测试连接」会调用 `config/test/fallback`，返回 40001「未知的配置分组」时网页隐藏该按钮（后端不必提供这个分组）。
- 数据统计：「拍照识别」「AI 问答」卡片各加「近 7 天备用模型」（vision_7d / chat_7d），趋势图加「备用模型」虚线（fallback_used）。
- 用户详情：识别记录加「模型」列，AI 对话的每条回答下方显示「模型：xxx」；`fallback` 为 true 时带「备用」标签，`model` 为 null 时识别记录显示 —、回答下方不显示。

## 八、模型自动备用（v2 新增）

AI 问答与拍照识别互为备用：问答主模型 DeepSeek（CHAT_MODEL）失败时改用通义千问（CHAT_FALLBACK_MODEL）；识别主模型通义千问（VISION_MODEL）失败时改用 DeepSeek（VISION_FALLBACK_MODEL，deepseek-flash 能看图）。App 不提示，只在后台记录。

### 8.1 新增配置项（系统配置，分组 `fallback`「自动备用」，均非密钥类）

| key | 说明 | 默认值 |
|---|---|---|
| AI_FALLBACK_ENABLED | 是否启用自动备用，取值 `true` / `false` | true |
| CHAT_FALLBACK_MODEL | AI 问答的备用模型（通义千问，用 DASHSCOPE_API_KEY） | qwen3.8-max |
| VISION_FALLBACK_MODEL | 拍照识别的备用模型（DeepSeek，用 DEEPSEEK_API_KEY） | deepseek-flash |

`GET admin/api/config` 的返回中出现这三项（group 为 `fallback`），修改 / 恢复规则与其他非密钥项相同。

### 8.2 接口新增字段

| 接口 | 新增字段 |
|---|---|
| GET admin/api/stats/overview | `fallback: {chat_7d, vision_7d}`：近 7 天由备用模型完成的 AI 回答数、识别数 |
| GET admin/api/stats/trend | `fallback_used: [..]`：每天由备用模型完成的回答数 + 识别数（与 dates 等长） |
| GET admin/api/sessions/{id}/messages | 每条消息新增 `model`（回答所用模型名，用户消息与旧数据为 null）、`fallback`（是否由备用模型回答，布尔） |
| GET admin/api/users/{id}/recognitions | 每条记录新增 `model`、`fallback`（同上） |

App 接口不变（不返回模型信息）。

## 实现说明（后端，与上文约定的差异与补充）

以下为后端实现时确定的细节；与上文表述不完全一致之处以这里为准。

**前端库**

- 最初用 WebJars 提供，但 Maven Central 上 Element Plus 的 WebJar 最新只有 2.1.10（2022 年），缺少网页用到的组件与属性（如 `el-button` 的 `link`）。
- 改为把 Vue 3.5.42、Element Plus 2.14.5、@element-plus/icons-vue 2.3.2、ECharts 5.6.0 的发布文件放在 `static/admin/vendor/`（见其中的 README.md），pom 中不再引入 WebJars。
- `AdminApiTest` 验证这 6 个文件都能访问。

**登录与安全**

- 40101 的文案为「请先登录」；CSRF 令牌缺失或不符返回 40301「无权限执行该操作，请刷新页面后重试」；会话 Cookie 名为 `PESTAI_ADMIN_SESSION`（Path=/admin）。
- `auth/login`：用户名或密码为空 40001；用户名不存在与密码错误都返回 40102「账号或密码错误」。第 5 次输错时直接返回 42901
  「登录失败次数过多，请 15 分钟后再试」；锁定期间的请求不校验密码、不计次数、不写日志。账号的失败次数在登录成功或被锁定后清零；
  同一 IP 的失败次数保存在内存中（重启清零），最后一次失败超过 15 分钟后重新计数。
- `auth/password`：原密码错误 40001「原密码不正确」；新密码 10–64 位、同时含字母和数字，否则 40001「新密码至少 10 位，并同时包含字母和数字」；
  与原密码相同 40001「新密码不能与原密码相同」。
- 修改 / 恢复密钥类配置时 `admin_password` 缺失或错误都返回 40001「管理员密码不正确」。

**数据统计**

- 「活跃」近似：t_user 只保存最近一次登录时间，因此「当天登录」只能算到之后没有再登录的那一次；一直保持登录（令牌 30 天有效）的用户
  只按识别 / AI 提问计入。「近 7 天」为含今天在内的 7 个自然日（Asia/Shanghai）。
- 识别次数、成功率、模式分布、结果前 10 都**包含用户已删除（逻辑删除）的记录**；后台彻底删除的记录、注销账号的数据不再计入。
  AI 提问 = role 为 user 的消息（删除对话后不再计入）。短信 = t_sms_code 行数：每发送一条验证码写一行，发送失败的已回滚不计入；
  注销账号会删除该手机号的验证码记录，因此历史短信数会相应减少。
- 比率保留 4 位小数，分母为 0 时为 0。`trend` 的 `days` 只接受 7 或 30（默认 7），其他值 40001。
- `distribution.modes` 的 name 为中文：「病虫害识别」（PEST）、「作物与杂草识别」（CROP）；`identities` 中清除了身份的用户显示为「未设置」；
  `crops` 按逗号 / 中文逗号 / 顿号拆分并清洗（与 App 用户画像规则相同），同一用户的同一作物只算一次。

**用户管理**

- 列表按用户 ID 倒序（新注册的在前）；`page ≥ 1`、`size` 1–100，超出 40001；`status` 只能是 NORMAL / DISABLED / 空，其他 40001；
  `keyword` 中的 `%`、`_` 按字面匹配。`recognition_count` 含用户已删除的识别记录。
- `session_count` 与 `users/{id}/sessions` 只统计 / 列出至少有 1 条消息的会话（与 App「历史对话」一致），按最后一条消息时间倒序，
  没有标题时为「新对话」。`sessions/{id}/messages` 会话不存在 40001「会话不存在」。
- 识别记录列表中失败记录的 `top_name`、`confidence`、`severity` 为 null；`confidence` 去掉末尾的 0（0.920 → 0.92）。
- `disable` 的请求体可以省略；对已停用的用户再次停用同样成功（再次让令牌失效）。用户不存在的操作返回 40001「用户不存在」。
- **`PUT users/{id}/profile` 的 identity / crops**（按网页需要确定）：
  - `identity`：字段缺失或为 null → 不修改；`""` → 清除为「未设置」（存 NULL）；种植户 / 家庭园艺 / 农技人员 → 修改；其他值（含只有空格）→ 40001
    「种植身份只能是种植户、家庭园艺或农技人员」。为此迁移 006 把 `t_user.identity` 改为可空（默认值仍为「种植户」）；
    App 读到 null 时按「种植户」显示，AI 用户画像按没有填写处理。
  - `crops`：字段缺失或为 null → 不修改；`""` → 清空；其他按 App 相同的规则规范后保存（拆分后为空同样清空）。
  - `nickname` 必填，最多 16 字（保存时去掉首尾空白）；`region` 不能在后台修改。
- `DELETE recognitions/{id}`、`DELETE sessions/{id}`：记录 / 会话不存在时直接成功（幂等，不写日志）。删除会话与 App 删除对话完全相同
  （消息、图片行、仍未被其他消息引用的聊天图片文件）。
- `deactivate`：`confirm_phone` 去掉首尾空白后必须与完整手机号相同，否则 40001「手机号不一致，请输入该用户的完整手机号」；已停用的账号同样可以注销。
- `reset-password` 的临时密码由字母和数字组成（去掉易混的 0 O 1 l I），满足 App 的密码规则（8–20 位、含字母和数字）。

**系统配置**

- 掩码：值不少于 12 位时为前 3 位 + `****` + 后 4 位；**不足 12 位只返回 `****`**（避免短值几乎全部露出）；未配置为空串。
- `source`：ADMIN（后台设置）/ ENV（环境变量或 .env 中有非空的同名变量）/ DEFAULT（与默认值相同）/ NONE（为空）；
  `updated_at`、`updated_by` 只在 ADMIN 时有值。列表按固定顺序返回第四节表中的 13 项。
- `PUT`：value 去掉首尾空白后不能为空、不能含换行等控制字符、最长 2000 字；非密钥类的 `DELETE` 请求体可以省略；未知的 key 40001。
- `POST config/test/{group}`：Key 未配置时不发请求，返回 `{ok:false, latency_ms:0}`；vision / chat 发一句「你好」（max_tokens 16），
  asr 发 0.5 秒静音（识别结果为空也算成功），时限 15 秒；失败说明最多 160 字，并把当前 Key 替换为 `****`。
  sms 必须带合法的 `phone`（否则 40001），走正常的 SmsService 发送一条**登录验证码**（同一手机号 60 秒限频照常生效，触发时 `ok:false` 并给出原因）；
  短信当前只打印日志（未配置齐全或 SMS_PROVIDER=log）时不发送，返回 `ok:false` 说明原因。未知分组 40001。
- 密钥类用 AES-GCM 加密保存，主密钥为环境变量 `PESTAI_CONFIG_SECRET`（未设置时由 JWT_SECRET 派生）；主密钥变更后旧密文无法解密，
  启动后按「未设置」处理（source 变回 ENV / NONE），需要重新填写。

**操作日志**

- `LOGIN_FAILED` 的 `admin` 为尝试登录的用户名（不存在的用户名 admin_id 为空）；`detail` 不记录密码、临时密码与密钥明文
  （密钥类配置只记「已更新（密钥类，值不记录）」，非密钥类记录新值）。写操作的日志在事务提交后才写入，操作失败不留日志。
- `action` 为空时不过滤；`size` 1–100。

**App 语音识别（POST pestai/v1/ai/asr）**

- 请求 DashScope 时带 `asr_options: {enable_itn: true, language: "zh"}`（官方兼容接口支持的参数）。
- 校验文案：没有文件 / 空文件 40001「请先录音」；不是 RIFF/WAVE 40001「只支持 WAV 格式的录音」；不是 PCM 40001「只支持 PCM 编码的 WAV 录音」；
  缺少 fmt / data 块 40001「录音文件不完整，请重新录音」；超过 2MB 40001「语音不能超过 2MB」；时长按文件头计算，超过 60 秒（留 0.5 秒余量）
  40001「语音不能超过 60 秒」。不强制 16kHz / 单声道（模型可以处理其他采样率），App 仍按约定录制。
- 每人每分钟 20 次只计通过校验、真正调用识别的请求，与 AI 提问的限流分开计数；单次识别时限 20 秒（小于 App 的 30 秒读取超时）。

**模型自动备用（八）**

- 配置项：三项排在 `GET config` 列表的最后（第四节的 13 项之后，共 16 项），`group` 为 `fallback`，`secret` 为 false，`label` 依次为
  「启用自动备用（true / false）」「问答备用模型（通义千问，用 DASHSCOPE_API_KEY）」「识图备用模型（DeepSeek，用 DEEPSEEK_API_KEY）」。
  与其他非密钥项相同，只多一条校验：`AI_FALLBACK_ENABLED` 只接受 `true` / `false`（不区分大小写，保存为小写），其他值 40001
  「AI_FALLBACK_ENABLED 只能是 true 或 false」。环境变量 / `.env` 中写成 `0` / `no` / `off` 同样视为关闭，空值按默认值 `true`。
  对应 application.yml 的 `ai-fallback.enabled`、`ai-fallback.chat-model`、`ai-fallback.vision-model`。开关、模型名与 Key 每次请求时读取，修改后立即生效。
- **`POST config/test/fallback`**（第四节的测试接口多了一个分组，网页可按需使用）：依次测试已配置 Key 的备用模型 ——
  问答备用（DASHSCOPE_API_KEY + CHAT_FALLBACK_MODEL，与正式调用一样 `enable_thinking: true`）、识图备用（DEEPSEEK_API_KEY +
  VISION_FALLBACK_MODEL，`reasoning_effort: none`），请求方式、时限与 chat / vision 测试相同。`ok` 为测试到的各项都成功，`latency_ms` 为合计，
  `message` 形如「问答备用：连接正常（模型 qwen3.8-max）；识图备用：HTTP 401：…」；没有 Key 的一项写「未配置 …，不会启用」；
  两项都没有 Key 时不发请求，返回 `{ok:false, latency_ms:0}`；开关为 false 时在 message 末尾注明，测试照常进行。
- 能否改用备用（问答、识图分别判断，每次请求时）：开关打开、备用模型的 Key 已配置、主模型不是 Mock（问答：DEEPSEEK_API_KEY 已配置；
  识图：DASHSCOPE_API_KEY 已配置）。不满足时行为与原来完全相同（问答没有首片段时限，识图主模型独占 25 秒）。
- **AI 问答**（`FallbackChatClient`）：
  - 只在主模型**送出任何思考 / 正文片段之前**失败时改用通义千问：HTTP 非 2xx、连接失败、流中返回 error、流没有以 `[DONE]` 结束，
    或开始请求后 **20 秒**内没有任何片段（取消主模型的上游请求；SSE 注释行不算片段）。已经送出片段后出错保持原行为
    （`[ERROR]` 50201，App 显示「回答中断」），不切换；客户端已断开（停止生成）时不切换。
  - 备用请求：DashScope 兼容接口（与识图同一地址），流式，`enable_thinking: true`（思考照常以 `event: reasoning` 推送，App 的思考区照常显示），
    温度与主模型相同，不传 `max_tokens`（主模型的 393216 是 DeepSeek 的上限）。消息与主模型完全相同（含 1–9 张图片）。
  - App 不感知：切换发生在任何内容写出之前，流的格式与正常回答相同；思考耗时 `reasoning_ms` 从开始请求主模型算起（包含切换前等待的时间）。
  - 备用模型失败（无论是否已送出片段）不再回到主模型，按原规则返回 `[ERROR]`。
  - 带图提问：`CHAT_IMAGE_INPUT=true`（默认）时与文字提问相同，主、备都直接看图；为 false 时仍改交识图模型（不经过自动备用），
    `model` 记为识图模型名、`fallback` 为 false。
- **拍照识别**（`RecognitionService.analyze`，上传识别与重新识别相同）：
  - 备用可用时主模型（含解析失败的那一次重试）最多 **15 秒**；调用失败（HTTP 错误、连接失败、超时）或两次输出都无法解析时改用 DeepSeek，
    用总时限 25 秒中剩余的时间（主模型用满 15 秒时约 10 秒），解析与重试规则相同。模型正常返回的「照片不清晰」（IMAGE_BAD）是有效结果，不切换。
  - 备用请求：DeepSeek chat/completions 非流式，与通义千问完全相同的系统提示（按 PEST / CROP）、图片与识图指令（含作物参考信息），
    `reasoning_effort: none`（DeepSeek 支持 none / low / high / max），温度取 vision.temperature；结果同样交给 VisionResultParser。
  - 备用模型也失败时按它的原因记录与返回（超时 50401，其他 50201），不再回到主模型。
  - App 不感知：识别结果的 `model_name` 仍为 VISION_DISPLAY_NAME（「通义千问」）。
- **熔断**：问答、识图各自独立。改用了备用模型的那次失败之后 **60 秒**内的请求直接交给备用模型（不先试主模型；识图时备用模型可用完整的 25 秒），
  60 秒后恢复为先试主模型，再失败则重新计时。只有「在任何片段之前的失败」才计入（问答中途出错不计）；状态只在内存中，重启后清零。
- **记录**（迁移 `sql/migrations/007_model_fallback.sql`；schema.sql 已同步）：
  - `t_ai_message.model`（VARCHAR(64) NULL）、`fallback`（TINYINT(1) NOT NULL DEFAULT 0）：只在 AI 回答上写入实际回答的模型名
    （如 `deepseek-flash`、`qwen3.8-max`；改交识图模型时为识图模型名；Mock 为 `mock`）；停止生成时保存的部分回答同样记录。用户消息为 NULL / 0。
  - `t_recognition.model` / `fallback`（同上）：识别成功与照片不清晰时写入给出结果的模型；识别失败为 NULL / 0。重新识别成功时覆盖；
    原记录是失败记录时（重新识别结果为照片不清晰 / 失败）一起更新；原记录是成功记录而重新识别失败时保持不变。
  - 迁移前的旧数据为 NULL / 0。**必须先执行迁移 007 再部署新版本**（保存回答、提问、识别记录都会写这两列）。
