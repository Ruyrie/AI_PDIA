## 五、业务组件写法

**Dagger**：本组件的 `di/XxxModule.java` 已建好并被 AppComponent 引用（不要改类名）。

```java
@Module
public abstract class HomeModule {
    @Provides @Singleton
    static HomeApi provideHomeApi(Retrofit retrofit) { return retrofit.create(HomeApi.class); }

    @Binds @IntoMap @ViewModelKey(HomeViewModel.class)
    abstract ViewModel bindHomeViewModel(HomeViewModel viewModel);
}
```

- Repository：`@Singleton` + `@Inject` 构造方法（注入 XxxApi、UserSession、ImageCompressor、Gson 等）。
- ViewModel：继承 BaseViewModel，`@Inject` 构造方法，**不要加 @Singleton**。需要 Intent 参数时由页面调用 `vm.init(...)`（自行防止旋转后重复初始化）。
- Api 接口名带组件名（HomeApi、MineApi…），即使路径相同也各自声明，避免 Dagger 绑定冲突。
- 需要在 Service / Adapter 中取依赖：在 `di/XxxDeps.java` 中声明方法（方法名加组件前缀，如 `recognizeRepository()`），用 `AppHost.deps(context, XxxDeps.class)` 获取。

**页面与路由**：每个 Activity 在本组件 AndroidManifest.xml 中声明（`exported="false"`，主题默认继承应用主题）：

```xml
<activity android:name=".ui.HistoryActivity" android:exported="false">
    <intent-filter>
        <action android:name="com.heban.pestai.action.HISTORY" />
        <category android:name="android.intent.category.DEFAULT" />
    </intent-filter>
</activity>
```

跳转一律 `startActivity(RouterPath.intent(context, RouterPath.SCAN).putExtra(...))`，不直接引用其他组件的类。

**Edge-to-Edge**：独立 Activity 的根布局调用 `InsetsHelper.applySystemBars(binding.getRoot())`（或按需 `apply(view, top, bottom, ime)`）。MainActivity 内的三个 Tab Fragment 顶部状态栏间距与键盘由 MainActivity 统一处理，Fragment 不要再加。MainActivity 隐藏的 Tab 生命周期停在 STARTED，`onResume()` 只在 Tab 可见时回调。

**资源命名**：本组件全部资源（layout 以外）加组件前缀，如 `home_`、`scan_`；layout 按 `activity_xxx / fragment_xxx / item_<组件>_xxx / dialog_<组件>_xxx` 命名，保证全工程唯一；View id 尽量带页面语义。字符串写进本组件 `res/values/strings.xml`（加前缀）。

**DataBinding**：布局用 `<layout>` 包裹并 `binding.setLifecycleOwner(this)`；表单双向绑定 `@={vm.phone}`（`MutableLiveData<String>`）。**不要在绑定表达式里写嵌套三元**（`a ? x : (b ? y : z)`）：DataBinding 为其生成的脏标记判断顺序有误，重新绑定（RecyclerView 复用、LiveData 变化）时内层结果不会计算，文字变空。多条件文字改用多属性 BindingAdapter（参见 module_record 的 `recordFooterText`、module_account 的 `accountSubmitLoading / accountSubmitSms`）。

**测试**：表单校验、格式化等写成纯 Java 工具类，在 `src/test/java` 用 JUnit 测试；ViewModel 测试用 `InstantTaskExecutorRule` + `RxJavaPlugins` / `RxAndroidPlugins` 把调度器替换为 trampoline。

## 六、后端约定（server/）

- `server/` 为 Maven 工程 pestai-server，包名 com.heban.pestai.server；JDK 17 语言级别（本机用 JDK 21 运行）。
- 所有接口挂在 `/pestai/v1/` 下；图片静态资源 `/files/**` 映射到配置的文件目录。本机开发时 App（模拟器）通过 `http://10.0.2.2:8080` 访问。
- 密钥与连接信息只从环境变量或本机的 `server/.env` 读取（`.env` 不提交，格式见 `server/.env.example`，说明见 `server/README.md`）；**未配置大模型 / 短信 Key 时自动使用 Mock / 日志实现**，便于联调。
- 模型：识图 `qwen3.8-max`（关闭深度思考），问答 `deepseek-flash`（文字与带图提问都由它回答）。若把问答模型换成纯文本模型，必须同时设置 `CHAT_IMAGE_INPUT=false`，带图提问会自动改用识图模型。
