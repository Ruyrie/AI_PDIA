## 一、问题与决定

| 问题 | 决定 |
|---|---|
| 申诉只要知道原手机号就能提交；昵称、最近登录时间、常用登录地区不做任何核对；也没有审核人员 | **删除整套申诉机制**（表、接口、管理员审核、ADMIN_KEY、时间线页面） |
| 原手机号不可用时如何证明是本人 | 只用**本人才知道的信息**自助验证：① 原手机号 + **登录密码**；② 原手机号 + **账号恢复码**（用户事先在设置里生成并自行保存）。验证通过后验证**新手机号**短信，立即换绑并自动登录 |
| 密码和恢复码都不记得 | 如实告知「无法验证身份，不能找回」，引导：其他设备仍登录着时到「设置 → 手机号」直接更换；或用新手机号注册新账号 |
| 没有人工客服 | 全 App 删除「人工」「客服」「审核」「申诉」字样（如 40301 文案改为「该账号已停用」） |
| 找回账号要不要填地区 / 昵称 / 登录时间 | **不要**，这些信息无法核实，填了也没有作用 |
| 密码错误次数限制 | 不限制（产品负责人决定） |
| 完善资料的「所在地区」 | **删除该字段**（产品负责人决定：没有实际用途）；不再申请定位权限。后端 region 允许为空，老用户已有的地区仍在「我的」页显示 |
| 登录页「+86 ▾」 | 只支持 +86，去掉下拉箭头 |

## 二、短信场景与模板（赠送签名「恒创联众」）

| 场景（SmsScene） | 发送对象 | 模板 | 配置项 |
|---|---|---|---|
| LOGIN / REGISTER | 登录 / 注册手机号 | 100001 | ALIYUN_SMS_TEMPLATE_CODE |
| CHANGE_PHONE | 新手机号（已登录更换） | 100002 | ALIYUN_SMS_TEMPLATE_CHANGE_PHONE |
| RESET | 账号手机号（找回密码） | 100003 | ALIYUN_SMS_TEMPLATE_RESET |
| REBIND（原 APPEAL） | 新手机号（找回账号） | 100004 | ALIYUN_SMS_TEMPLATE_REBIND |
| DEACTIVATE | 当前手机号（注销） | 100005 | ALIYUN_SMS_TEMPLATE_VERIFY |
| RECOVERY（新增） | 当前手机号（生成恢复码） | 100005 | ALIYUN_SMS_TEMPLATE_VERIFY |

`auth/sms/send` 接受 LOGIN / REGISTER / RESET / REBIND（REBIND 时新手机号已注册返回 40901）；CHANGE_PHONE、DEACTIVATE、RECOVERY 只能通过需要登录的接口发送。

## 四、接口（相对 `{BASE_URL}/pestai/v1/`，JSON 下划线命名）

| 方法 | 路径 | 登录 | 请求 | 返回 data | 错误码 |
|---|---|---|---|---|---|
| POST | auth/recover/verify | 否 | `{"old_phone","method":"PASSWORD"\|"RECOVERY_CODE","password"?,"recovery_code"?}` | RebindTicketVO（rebind_ticket、expire_in=600、method） | 40104 未注册；40102「账号或密码错误」；40105「恢复码错误或已失效」（未生成也返回它）；40301 已停用；40001 参数 |
| POST | auth/recover/rebind | 否 | `{"old_phone","rebind_ticket","new_phone","code","new_password"?}` | LoginVO（新令牌，is_new=false） | 40001（凭证无效 / 过期 / 已用，message「验证已过期，请重新验证身份」；新号与原号相同；method 为 RECOVERY_CODE 却缺少合规 new_password）；40103；40901 |
| GET | user/recovery-code | 是 | — | RecoveryCodeVO（generated、created_at，recovery_code 为空） | — |
| POST | user/recovery-code/sms | 是 | `{}` | null（验证码发往当前手机号，场景 RECOVERY） | 42901 |
| POST | user/recovery-code | 是 | `{"code":"123456"}` | RecoveryCodeVO（generated=true、created_at、**recovery_code 明文只返回这一次**） | 40103 |

规则：

- 恢复码：12 位，字符集 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（去掉易混的 0/O/1/I），显示为 `ABCD-EFGH-JKLM`；只存 BCrypt 哈希；校验时忽略大小写、空格和连字符；重新生成后旧码立即失效；**用于找回账号后立即失效**（recovery_code_hash 置空）。
- rebind_ticket：32 位随机串，库中只存 SHA-256 摘要，10 分钟有效，一次性，绑定到原手机号对应的用户（复用 t_reset_ticket，purpose 区分）。
- 换绑（auth/recover/rebind）在一个事务内：校验凭证 → 新号≠原号且未注册 → 核销新号的 REBIND 验证码 → 更新 phone；method 为 RECOVERY_CODE 时**必须**带 new_password（8–20 位、字母 + 数字）并更新密码、清空恢复码；method 为 PASSWORD 时 new_password 可选（带了就更新）→ token_version + 1、更新 last_login_at → 凭证置为已用 → 签发令牌返回 LoginVO（本机直接登录，其他设备失效）。
- ErrorCode：40301 文案「该账号已停用」；新增 40105「恢复码错误或已失效」。
- 删除：申诉相关的 Controller / Service / Mapper / 实体 / 请求 / VO、`admin/**` 接口与 AdminKeyInterceptor、`pestai.admin-key` 与 ADMIN_KEY 环境变量、SmsClient.sendNotice、换绑 / 注销流程中处理申诉的代码。

## 六、恢复码引导与「刚验证过短信免再次验证」（补充，已和产品负责人确认）

**问题**：用验证码登录后马上去生成恢复码，需要再收一条短信；阿里云短信认证对同一手机号默认 60 秒只能发 1 条（不分模板），于是提示「操作太频繁」。

**规则（参考 GitHub 等的「近期已验证」模式）**：用户刚通过短信证明手机号归属后 **10 分钟内**，生成恢复码不再要求短信验证码。

| 何时记为「刚验证过短信」 | 写 t_user.sms_verified_at = 当前时间 |
|---|---|
| 验证码登录（含新用户自动注册） | auth/login/sms |
| 密码注册 | auth/register |
| 已登录更换手机号成功 | PUT user/phone（新手机号已验证） |
| 找回账号换绑成功 | auth/recover/rebind（新手机号已验证） |

密码登录不算（仍需短信验证码）。

**界面**

| 场景 | 交互 |
|---|---|
| 新用户注册后 | 密码注册（A05）或验证码登录新用户（is_new）进入 A06 完善资料；A06 点「开始使用」或「跳过」/ 返回后，**先打开 A12 引导模式**，再进入首页 |
| A12 引导模式 | Intent 布尔参数 `from_register`（module_account 内部常量）。标题「保存账号恢复码」；说明「账号已创建。建议现在保存账号恢复码：手机号停用又忘记密码时，可以用它找回账号。」+ 原说明列表；按钮「生成恢复码」；文字按钮「稍后再说」→ RouterPath.MAIN 清空任务栈。生成后显示恢复码、「复制」、复选框「我已抄写或截图保存」，勾选后「完成」→ RouterPath.MAIN 清空任务栈。系统返回键等同「稍后再说」（已生成但未勾选时二次提醒）；生成失败显示原因 +「重试」 |
| A12（两种模式通用） | 进入时 GET user/recovery-code；`verify_required` 为 false 时**隐藏短信验证码区域**，显示一行提示「你刚刚已通过短信验证，可以直接生成」，「生成恢复码」直接可点（请求不带 code）；为 true 时保持现有的「验证当前手机号 + 验证码」流程。若直接生成时服务器返回「请先验证当前手机号」（10 分钟窗口刚好过期），自动切换为需要验证码的界面 |
| 未生成提醒 | M01「我的」页资料区下方显示提醒卡片（warningContainer 底、圆角 16dp）：key 图标 +「你还没有保存账号恢复码」+「手机号停用又忘记密码时，可以用它找回账号」+ 按钮「去生成」（RouterPath.RECOVERY_CODE）+ 右上角关闭；关闭后 7 天内不再显示（本机按用户 ID 记录）；已生成、游客、状态查询失败时不显示；onResume 刷新 |
