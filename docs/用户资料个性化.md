# 用户资料个性化（种植身份与主要作物生效）

| 项目 | 内容 |
|---|---|
| 所属项目 | AI 病虫害识别助手 |
| 来源 | 注册 / 完善资料时填写的种植身份（`t_user.identity`）和主要作物（`t_user.crops`）此前只保存、不影响任何功能 |
| 涉及组件 | server（AI 问答提示词、大家常问、拍照识别，已完成）、module_ai / lib_common（大家常问显示「按你种的…推荐」） |
| 数据 | 不改表、不需要迁移脚本；identity 为种植户 / 家庭园艺 / 农技人员，可空；crops 为逗号分隔字符串，可空 |

## 一、生效范围

| 功能 | 身份 | 主要作物 |
|---|---|---|
| AI 问答（`POST ai/sessions/{id}/messages`） | 用 | 用 |
| 大家常问（`GET ai/suggestions`） | 不用 | 用（新增 `crop` 字段） |
| 拍照识别（`POST recognitions`、`POST recognitions/{id}/retry`，PEST / CROP 两种模式） | 不用 | 用（参考信息） |

资料修改后下一次请求立即生效（每次请求都从 `t_user` 读取，不缓存）。

## 二、AI 问答：系统提示中的「用户画像」

系统提示的顺序：角色设定 → **用户画像** → 识别结论（追问识别结果时）→ 输出格式约定，段落之间空一行。身份和作物都没有时不加这一段。

用户画像段落为「用户画像：」单独一行，其后身份一行（没有身份时省略）、作物一行（没有作物时省略）。文字在 `server/src/main/resources/prompts/chat-profile.txt`（每行「键=内容」，修改后重启生效）：

| 身份 | 发给模型的一行 |
|---|---|
| 种植户 | 用户是种植户（规模化田间 / 大棚生产）。给田间可操作的办法，用药写明有效成分、稀释倍数或亩用量，提醒安全间隔期与轮换用药。 |
| 家庭园艺 | 用户是家庭园艺爱好者（阳台、庭院、盆栽等少量种植）。优先给物理防治与低毒方法，药剂选家庭能买到的小包装低毒产品，提醒避开儿童与宠物，不推荐高毒农药。 |
| 农技人员 | 用户是农技人员。可以使用专业术语，说明病原 / 发生规律、药剂有效成分与作用机理、抗性管理，必要时给出诊断要点。 |

作物一行：「用户主要种植：番茄、黄瓜、小麦。问题没有说明作物时，可优先结合这些作物回答；问题已经说明了其他作物时以问题为准，不要硬套。」

示例（种植户，作物「番茄,黄瓜,小麦」）：

```
用户画像：
用户是种植户（规模化田间 / 大棚生产）。给田间可操作的办法，用药写明有效成分、稀释倍数或亩用量，提醒安全间隔期与轮换用药。
用户主要种植：番茄、黄瓜、小麦。问题没有说明作物时，可优先结合这些作物回答；问题已经说明了其他作物时以问题为准，不要硬套。
```

Mock 问答客户端只从系统提示中取识别结论，不受这一段影响。

## 三、大家常问：`crop` 字段

挑选规则不变：适用作物与用户主要作物有交集的问题排在前面，每天轮换，最多 3 条。SuggestionVO 新增可空字段 `crop`：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | number | 不变 |
| text | string | 不变 |
| crop | string / null | 新增。按作物挑中的问题为匹配到的作物名：用户作物（按填写顺序）中第一个属于该问题适用作物的；通用问题、与用户作物无关的问题、用户没有填写作物时为 null（字段保留，不省略） |

示例（秋季，用户作物「番茄,黄瓜」）：

```json
{"code":0,"message":"ok","data":[
  {"id":301,"text":"番茄叶片发黄卷曲是什么原因？","crop":"番茄"},
  {"id":302,"text":"黄瓜叶子发黄卷边是什么原因？","crop":"黄瓜"},
  {"id":305,"text":"秋季大棚白粉病怎么防治？","crop":null}
]}
```

App 取各条非空 `crop` 去重后显示说明「按你种的番茄、黄瓜推荐」；全部为 null 时不显示。旧版 App 忽略未知字段，不受影响。

## 四、拍照识别：作物参考信息

用户填写了主要作物时，识图请求的 user 文字在原指令后另起一行附参考信息（PEST、CROP 两种模式和重新识别都一样）：

```
请识别这张照片，严格按要求只返回一个 JSON 对象。
参考信息：该用户主要种植番茄、黄瓜、小麦。仅当照片中的作物种类难以判断时参考；照片能明确看出作物时以照片为准，不要因为这条信息改变判断。
```

- 没有作物时指令与原来完全相同；种植身份不用于识图。
- 系统提示（JSON 输出约定）不变，结果仍按原规则解析校验；只多一行短文字，作物在开始计时之前读取，不影响 25 秒的时间预算。
- Mock 识图客户端忽略参考信息（同一张图结果不变）。

## 五、输入清洗（防止借资料写入指令）

身份和作物都是用户填写的内容，进入提示词前统一清洗（`UserProfile`）：

| 项 | 规则 |
|---|---|
| 身份 | 去掉首尾空白后必须是「种植户」「家庭园艺」「农技人员」之一，否则视为没有填写 |
| 作物拆分 | 按英文逗号、中文逗号、顿号拆分，去掉空项与重复项 |
| 字符 | 换行、制表符等控制字符、标点、表情都替换为空格（连续空格合并、去掉首尾空格）；只保留文字、数字和 `·-/()（）` |
| 长度 | 每项最多 20 个字（超出截断），最多 10 项（多余的忽略） |

因此作物只会以一行、顿号分隔的名称出现在提示词中，无法写入多行或成句的指令。保存资料时的规范化（`PUT user/profile`）不变。
