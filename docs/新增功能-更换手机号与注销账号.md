## 一、需求与已确认的决定

| 场景 | 规则 |
|---|---|
| 更换手机号（已登录，原手机号可能已不可用） | 设置 → 手机号 → 输入新手机号并验证**新手机号**收到的验证码即可换绑；不需要验证原手机号 |
| 新手机号已被其他账号使用 | 不允许换绑，提示「该手机号已注册，请先注销该账号或更换其他号码」 |
| 换绑后的登录状态 | **本机保持登录**（服务器返回新令牌），其他设备上的登录全部失效 |
| 未登录、原手机号不可用、密码也忘记 | 登录页 → 忘记密码 → 「手机号已停用」→ A09 申诉：填写账号信息、验证新手机号并**设置新密码**；人工审核通过后，账号换绑到新手机号，密码同时改为新密码，原有登录全部失效 |
| 注销账号 | 设置 → 注销账号；验证**当前手机号**的验证码 + 勾选已了解后果 + 二次确认后**立即注销** |
| 注销的后果 | 账号资料、全部识别记录与照片、全部 AI 对话与图片、头像、找回密码凭证全部删除，无法恢复；该手机号可以立即重新注册，得到的是全新账号 |
| 原手机号不可用时想注销 | 先通过 A09 申诉把账号换绑到可用的手机号，再注销 |

## 二、短信模板（阿里云号码认证服务 · 短信认证，赠送签名「恒创联众」）

| 场景（SmsScene） | 发送对象 | 模板 CODE | 模板名称 | 配置项（环境变量） |
|---|---|---|---|---|
| LOGIN / REGISTER | 登录 / 注册手机号 | 100001 | 登录/注册模板 | ALIYUN_SMS_TEMPLATE_CODE |
| CHANGE_PHONE | 新手机号 | 100002 | 修改绑定手机号模板 | ALIYUN_SMS_TEMPLATE_CHANGE_PHONE |
| RESET | 账号手机号 | 100003 | 重置密码模板 | ALIYUN_SMS_TEMPLATE_RESET |
| APPEAL | 申诉的新手机号 | 100004 | 绑定新手机号模板 | ALIYUN_SMS_TEMPLATE_APPEAL |
| DEACTIVATE | 当前手机号 | 100005 | 验证绑定手机号模板 | ALIYUN_SMS_TEMPLATE_VERIFY |

验证码规则不变：6 位数字、5 分钟有效、用后作废、同手机号同场景 60 秒限频（42901）。

## 三、接口（相对 `{BASE_URL}/pestai/v1/`，JSON 下划线命名）

| 方法 | 路径 | 登录 | 请求 | 返回 data | 错误码 |
|---|---|---|---|---|---|
| POST | user/phone/sms | 是 | `{"new_phone":"13900001111"}` | null | 40001 手机号格式不对 / 与当前手机号相同（message「新手机号不能与当前手机号相同」）；40901 已注册；42901 |
| PUT | user/phone | 是 | `{"new_phone":"13900001111","code":"123456"}` | LoginVO（新 token、更新后的 user、is_new=false） | 40103；40901（校验通过后被他人抢注）；40001 |
| POST | user/deactivate/sms | 是 | `{}` | null（验证码发往当前手机号） | 42901 |
| POST | user/deactivate | 是 | `{"code":"123456"}` | null | 40103 |
| POST | auth/appeal | 否 | 原有字段 + `new_password`（8–20 位，同时包含字母和数字） | AppealVO | 原有错误码；new_password 不合规为 40001 |

- `auth/sms/send` 仍只接受 LOGIN / REGISTER / RESET / APPEAL；CHANGE_PHONE、DEACTIVATE 只能通过上表需要登录的接口发送，手机号由服务器决定（DEACTIVATE 发往当前账号手机号），不能被用来向任意号码发码。
- 更换手机号成功：t_user.phone 改为新号、token_version + 1（其他设备的令牌失效），按新 token_version 签发新令牌放入 LoginVO 返回；App 用 `UserSession.saveLogin()` 保存，本机保持登录。
- 注销成功：在一个事务内删除该用户的 t_ai_message、t_ai_session、t_recognition（含已逻辑删除的）、t_reset_ticket、该手机号的 t_sms_code、该手机号作为原手机号的待审核申诉，最后删除 t_user；事务提交后尽力删除磁盘上的头像、识别照片、聊天图片文件。之后该用户的任何旧令牌都会因用户不存在返回 40101。
- 申诉审核通过（admin/appeals/{appeal_no}/approve）：phone 改为 new_phone，若申诉带有 new_password_hash 则同时更新 password_hash，token_version + 1。
